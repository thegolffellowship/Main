## 5. Traps and gaps for the next session

- GG truncates `<option>` labels in the results widget's round selector
  (~28 chars). Never parse dates from them; use the calendar widget.
- The sandbox cannot reach golfgenius.com (proxy policy) — every portal
  read goes through `probe_golf_genius` on production; raw widget pages
  are >70 KB of New Relic script before the body, so use the
  `calendar=` bridge, not `extract=raw`.
- MCP calls time out near 60 s: Phase A with `@40`, field walks with
  `field-bg=` (600 s budget) polled via `holes-status`.
- The Anthropic API proxy returned a 502 once mid-run; the engine is
  idempotent, a re-run cost nothing.
- Board affiliation is TODAY's (`TGF San Antonio` / `Former` / `Guest`),
  so "distinct member-ever" is what the archive can say; per-season
  membership needs Kerry's exports (channel 2) or the 2007-era Excel.
- tgf-sa2021 Phase A: 1 of its standings pages parsed; check
  `gg_history_pages.fetch_status` for that portal (`no_widget_data`
  rows re-run when the widget type list grows).
- The holes walk for 2019–2024 is now unblocked in principle (calendar
  dates land on `gg_history_events`, which the holes walk reads by
  round_index — it still needs `gg_round_index`, which the field walk
  stamps). Not run in this lane: scope was participation.
